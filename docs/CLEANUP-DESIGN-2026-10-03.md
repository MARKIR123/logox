# LOGOX 清理与流畅性优化设计（2026-10-03）

## 目标与边界

先测输入、流式、滚动、展开、缩放的主线程成本，再做保持功能的改进。保留两种 TUI 模式、Ctrl+T / Ctrl+O / Ctrl+B、终端历史、权限、压缩恢复与入梦会话归属。LEGACY 禁读禁改；会话、自动记忆、私有材料和测试证据不作为无用文件删除。

## 已查明的问题

1. Screen 每帧 fit_lines 检查所有历史行的格宽；即使行对象未变也重新计算。格宽检查不能删除，否则中文超宽会导致整个画面错位。
2. TimelineComponent 每帧遍历内容键、生成片段和区间，再把所有片段展开为行。保留内容键校验，防止原地修改老卡片被漏掉；先根据测量确定是否需要更深改造。
3. Fullscreen 滚动条每帧复制可见行，破坏 ANSI 身份复用。可以在底层不可变行、栏位字符、样式、宽度相同时复用组合行；滚动、缩放、选择及主题变化必须失效。
4. TimelineBuffer 的 _pending_delta / _pending_reasoning 只有读取与清空，没有写入；现行增量完全由 StreamSmoother 管理。_call_names 只写不读。确认全项目引用后清除旧私有字段与回退。
5. src/logox/tui/app.tcss 属于已移除的 Textual 界面，需核查当前打包、测试与公开配置承诺；兼容公开 API 不按零内部引用直接删除。

## 初步实现契约

格宽保护复用上一帧不可变 Text 与对应切分结果，宽度变化重新检查，仅持有当前帧行避免泄漏；不缓存可原地修改的消息 Block。输入输出仍是 list[Text]，超宽行沿用原始切分与样式。

滚动条缓存只持有本次视口对应行，键含不可变行对象身份、最终追加字符和样式、终端宽度；选区先生成新对象，自然失效。滚动条点击的轮次索引仍由完整区间更新。

业务审计覆盖事件、轮次/工具终态、压缩状态、存储、入梦调度、权限与工具；只有证据明确且行为等价的冗余直接整理，影响产品语义的选择单独讨论。

## 验证

离线基准记录同机同脚本、100 / 800 / 3200 对历史两模式输入、流式和展开帧中位耗时及 cProfile 热点；不是 Windows Terminal 真实输入延迟。新增测试应验证未变行跳过检查、新对象/缩放重检、缓存释放、中文/样式保持、选择与阅读锚点不变。保留现有 TUI/业务测试，结束后跑全量并记录实际数量；不连接真实模型或改用户档案。

## 文件清理原则

先检查 tracked、引用、文件内容类型与来源。只清理明确废弃界面资源、无写入字段与未使用导入；未知文件和 generated 用户记忆保持。根目录误生成的缓存先定位原因，再决定安全删除或隔离；禁止用批量后缀匹配删除数据。

## 基线与进一步收敛

假终端每场景 15 帧，中位数（ms）：800 对主屏输入 10.890、流式 11.129，全屏输入 7.721、流式 7.769；3200 对分别 55.785 / 57.655 / 43.668 / 40.058。cProfile 显示主屏格宽兜底和两模式片段/区间/字典重建是主要重复工作。输出不会改成跳过真实内容核验：render_cached 每帧仍比较每块显示键，但无变化时复用分块结果及行区间，避免新建数千临时对象。UI 行拼装复用共同片段前缀，只切与拼装变化后缀；不改变公开完整 Text 兼容入口。底层 Screen 行宽缓存只保留上一帧及当前帧输出。

编辑器 apply_completion 在 return 后存在不可达 _history_index 重置，导致从历史草稿接受补全后仍停留旧历史浏览状态。将重置放回返回前，与普通编辑结束历史选择保持一致，增加真实键序列验证。

## 业务与流式缓冲补充

StreamSmoother 每次释放最多 16 字符后，都会用 buffer[step:] 复制全部剩余积压；大输出会重复复制同一批字符。改为双通道独立 deque + 头片段偏移 + 字符计数；每次只复制本次释放内容。步长算法、公开 feed/step/pending/flush/clear 接口、末帧排空、中文顺序保持，计数 O(1)。

InlineApp 当前在 ModelRequestFinished 就把 _busy 置假，但一轮用户任务可包含后续工具、重试及摘要补写，尚未结束。忙状态保持到 TurnFinished；模型请求结束只排空显示，不允许此时 reload/model/session 变更穿过既有忙守卫。测试覆盖请求完成、工具开始、完整轮次结束与错误/取消路径。

公开 palette_css_variables 虽没有内部运行调用，但被 __all__ 导出且有独立契约测试，保留兼容；删除未被装载的 app.tcss，并纠正文档注释，避免宣称仍使用 Textual。不因静态无引用删除插件/工具扩展接口。

AST 扫描 118 个 Python 源文件，单引用候选中配置验证器与 slash 方法由装饰器/getattr 动态调用，必须保留。确认 shell._decode_bytes、format._prefer_break、format._split_oversized、Compactor._is_index_message 无任何源码、测试或当前模块文档调用，且不在公开 __all__ 中；移除这些旧私有实现，公开 is_index_message、现用换行算法和流式 Shell 编码器保持。

根目录 nul 为 56 字节 npm 路径查询输出；%SystemDrive% 是误创建的 7 个 Windows cache DB、约 934 KiB（956256 字节），不是 LOGOX 会话。将这两项搬至忽略的 .test-tmp/cleanup-quarantine-2026-10-03，可恢复；不删除全量临时目录或未知资料。生成的项目 ANAMNESIS.md 添加根级忽略，保留正文。

## 文件工具准备阶段的流畅性

edit.run 的读文件、四级匹配和 Diff 计算目前直接执行在主事件循环。延用已采用的只读 IO 后台线程路线，将纯准备阶段拆为 _prepare(target, args)，返回最终字节、统计、hunks 和匹配说明，或既有 ToolResult 失败。后台准备不修改源文件；取消可立即退出 await，残留只读计算不会继续写文件。返回后重新检查 ctx.is_cancelled，再在原有同步提交区间写临时文件并 replace。write 的既有文件统计读取同样放入只读准备线程，返回后再次检查取消。

快照/replace/成功结果发布路径保留，避免直接把整个写操作放后台后出现“显示已取消，后台仍修改源文件”的故障。线程不能立即终止 Python 计算，也不保证完全消除 GIL 争用；同步提交与 CAS 快照仍有磁盘延迟，此边界写进报告，后续若需要全部后台提交须另做提交/取消状态设计。验收添加取消发生在准备过程中源文件不变、事件循环可运行和提交成功结果一致的测试。

## 展开交互的缓存边界

Ctrl+T / Ctrl+O 只改变思考/入梦或工具/Diff 卡片的展示，但原来会清空整个时间线缓存，连普通正文与用户历史都重新排版。把展开开关移到相应种类块的内容键，普通正文键不受影响；单卡展开同样依靠 expanded 实际字段核验。快捷键与鼠标切换不再调用整段 invalidate，宽度、主题、清空等显式失效保留，阅读锚点仍照常恢复。测试断言展开时普通用户/正文不重排，并与全量无缓存输出对拍。

后台准备扩大了外部编辑可能发生的时间段，因此 edit 在提交前比较源文件当前字节与准备时原始字节；不同则返回可回灌的明确失败，要求重新读取再编辑，禁止覆盖中途外部修改。最终核对、replace 与既有 CAS 快照仍是同步成本，不将线程迁移描述为完整事务或 OS 沙箱。write 本身是明确全量重写语义，保持原规则。
