# 09 · Anamnesis 入梦

维护日期：2026-10-01。实现分支：`codex/anamnesis`，沿用项目工作目录。设计批准记录见 [实现设计](../ANAMNESIS-DESIGN.md) §17；本页描述代码实际行为。

## 1. 定位与边界

入梦在 TUI 打开、用户离开且前台任务结束时整理记忆。白天小憩回顾会话；本地时区 00:00—08:00 启动长眠，可只读研究当前项目代码。两者都无总时长截止；已有长眠跨过 08:00 不降级、不强制停止。没有新增会话、代码变化或未完工作时正常结束。

首版模型没有源码写入、Shell、测试、实验、MCP、插件或钩子入口。宿主只更新用户 `~/.logox/ANAMNESIS.md`、当前目录 `ANAMNESIS.md` 和 `~/.logox/anamnesis/` 辅助记录。文件、权限规则和工具注册表不来自前台的模型任务。应用限制不能代替操作系统沙箱。

类名前缀按用户裁定使用 `Anamesis`；目录、配置、命令和文件名使用 `anamnesis` / `ANAMNESIS.md`。不提供 `DreamCoordinator` 别名。

## 3. 机制

### 3.1 生命周期与多窗口

自动资格按项目汇总全部仍打开的窗口：每个窗口最后用户活动和前台结束两者取较晚时间，超过 `idle_seconds`；全部窗口的模型、工具和审批均已结束。`ModelRequestFinished` 只是一次模型请求结束，不代表整轮工具循环结束；服务直到 `TurnFinished` 才开始重新计算空闲时间。

用户真正提交普通消息或执行 `/anamnesis stop` 才设置停止标志，暂停当前窗口的入梦。输入、粘贴、删除、滚动、展开和只读 slash 只刷新活动时间，影响下一次自动启动资格；未发送草稿不递增资料世代、不取消当前生成、不使提案失效。普通消息在启动前台前先发出暂停，前台互斥保护继续生效；单次 Esc／Ctrl+C 不专门暂停入梦，既有退出操作仍关闭 TUI。没有跨窗口唤醒：另一窗口的消息提交不停止当前任务。关闭 TUI 同步禁止新启动，随后等待模型与工作线程收尾，不保留守护进程。

同一用户通过操作系统文件锁（file lock）保证只有一个入梦任务，避免多个进程同时更新用户档案；锁随进程退出释放。先按规范 cwd 分组全部存活窗口，确认项目全员资格，再选最近提交会话承载。禁用功能／未配置模型的窗口仍参与项目资格；最近会话无法运行时不改用旧会话偷偷入梦。项目按最后用户指令提交时间从新到旧，完成／暂停并收尾后标记已服务，优先轮转其它合格项目；新提交清除本项目已服务标记，不抢占运行中的任务。开始准备前与认领时共用候选检查。

窗口每 2 秒发布登记，心跳超过 20 秒或进程退出则不候选；状态跨进程存在传播间隔，不能宣称实时读到其它窗口的新按键。新用户记录保存原事件时间，重开／热切换读取当前会话最后提交时间；旧记录来源时间为 null（未知），队列没有可确认提交时间时内部排序哨兵仍为 0，稳定次序处理并列，不使用文件 mtime 冒充精确提交。手动入梦指令视为当前会话的新提交，沿用跳过空闲时长的规则，仍拒绝同项目其它窗口前台忙。

### 3.2 资料、工具与分析

每次运行只扫描当前项目会话桶和源码；其它仍打开项目由自己的队列任务整理，关闭项目不纳入本轮研究。用户画像从当前项目的明确用户表述更新，旧用户档案保留；项目档案只接受当前规范 cwd 来源。旧会话没有 cwd 元数据时仅在当前分桶内归属本项目；明确声明其它 cwd 的条目不混入。大用户消息按片段拆分，来源带物理行号、内容摘要值和片段偏移；回滚后旧来源失效，回滚记录自身作为重新核验线索。

资料处理游标保存已完成来源 ID。未形成完整提案（含步骤保护返回）的批次保留分析、代码来源、checkpoint 与报告，但不推进游标；持久化 `automatic_block` 保存待审来源集合摘要、代码指纹和暂停原因。自动调度发现资料相同便停止重试，不再创建运行器／追加开始事件；同项目其它窗口、昼夜切换和重开同样遵守。手动 `/anamnesis nap`／`sleep`、真实新来源或代码指纹变化可继续，不跳过未完成资料。草稿或仅改变界面活动世代不能解锁。代码指纹沿用路径／mtime／size 元数据，不是内容 hash；同尺寸且保留时间的外部改动可能无法自动识别，此时需手动继续。资格登记区分“没有可运行工作”和“窗口不空闲”，暂停窗口不冒充活跃窗口。未变会话复用扫描缓存；**改变的 JSONL 会重新扫描**，不是已实现的字节级尾部增量读取。损坏尾行和超过 1MiB 的单条记录留下覆盖缺口，不能报告为全文已读取。工具正文以可核对节选和归档指针提供，不自动读取所有工具大日志。

小憩只提供 `source`、`record_analysis`、`propose_memory`。长眠额外提供 `read`、`glob`、`grep`；文件受当前目录、敏感路径、LEGACY、链接和大小边界约束。搜索复用 ripgrep，接受既定正则／编码兼容变化。现有权限检查返回 ASK 或 DENY 时直接拒绝，不弹出无人值守审批。

模型明确输出阶段分析：问题、原文依据、判断原因、替代方案、结论及不确定性。分析 ID 不可原地覆盖，修订用新 ID 引用旧分析；每批提供新 ID 前缀以减少续做冲突。提案不必复制已 record_analysis 的分析：`analyses=[]`，变更以 `analysis_record_id` 引用原记录。重复改写反馈说明冲突 ID、不同字段和合法引用方式；未知来源列出实际非法身份，要求完整 source_id，不按前缀猜测；JSON 修复携带具体原因。阶段说明在结构化记录完整返回后展示；实际 reasoning 增量实时预览并落盘，核查请求同样提供过程通道。片段明确标为未核验，不能直接提交事实；模型没有返回思考时说明尚未收到，不从文件名编造内心过程。续做只把最近分析的短摘要放进下一次模型输入，完整旧分析保留在外置记录。

整理、契约修复和独立语义核验均不传 `max_tokens`，也不因思考／正文累计超过 120000 字符而终止。输入预算仍预留四分之一窗口（至少 512 token）给生成，拒绝过大的输入；这不是输出限额。本地服务自己的生成默认值、终止符和实际窗口仍生效，`request_timeout_s` 只限制连续无模型数据的等待（默认 180 秒）；收到正文、思考或原始工具参数分片即延期，持续生成不受请求总时长限制。HTTP 连接／写入／读取仍有各自等待保护，真正超时的原因明确记录；取消仍保留片段。适配器兼容 `reasoning_content` 与 Ollama `reasoning`，同分片两个字段只选一份；未返回内容不补造。

每次请求收尾写入 `model_response` 事件：`result` 是 JSON，包含归一化结束原因、请求上限（本功能为 null）、服务报告的用量或 null、实际收到的思考／正文字符数、完整工具数和 `failure_reason`。没有用量不填假 0。服务报告截断时保留收到的过程并拒绝提交，即使半截生成的正文碰巧是合法 JSON，也不当作成功；失败卡片说明截断与实际报告用量。

### 3.3 活档案与保存

稳定 `entry_id` 对同一事实进行替换、删除，避免无限追加。用户／项目正文分别最多 800／1600 估算 tokens。新增或替换必须有明确来源、独立理由、对应阶段分析；候选不自动入档。程序检查身份、作用域、旧值、来源有效性及预算，再用独立模型请求核对证据语义。项目变更另核对当前有效资料中的最新非 assistant 时间：只有不早于该界线的真实来源或本次可核验的当前文件才能作为当前状态依据；仅有旧快照、未知时间或模型转述留作候选。当前文件不能为无关的历史测试／git 状态背书，仍由语义核验审查。用户明确偏好不按项目资料时间自动失效。语义检查仍可能误判，不能据此声称记忆绝对正确。

每份档案：锁定 → 核对基础版本与来源 → 保存旧版和 prepared 记录 → 再检查唤醒与外部修改 → 同目录临时写入、同步并替换 → 保存机器条目元数据和 committed 记录 → 推进该作用域游标。**这是面试常考的：原子写（atomic write）**，面试官会追问进程在替换后崩溃怎么办。这里通过准备记录和新旧摘要值恢复，不把单文件替换当成两个 MD 的整体事务。

完整批次按条采纳：合格条目保存；拒绝和模型显式 candidate 只保留在事件／预览／报告，不写入 MD，也不加载为前台背景记忆。展示状态归一 candidate，报告保留原提案状态和拒绝原因。有效资料审阅完成后推进来源游标，表示“已审阅”而非“全部入档”；全部候选也正常完成／续做，不反复阻塞同批。后续证据可重新分析，但首版没有独立候选重试任务系统。生成不完整、核验 JSON／字段／身份错误、档案外部修改、预算／磁盘／版本冲突和取消仍按失败／暂停保护处理；来源失效的条目不得提交，提交时再次核对摘要值。单次提交只修改本批结果，不回写旧批同身份的报告条目。

如果 MD 已经手工修改、缺少匹配的机器元数据或目标是链接，则保留提案并停止自动覆盖。撤销 API `ArchiveStore.revert(change_id)` 创建反向版本，当前内容与版本不匹配则拒绝；首版未提供 slash 撤销／手工档案接管界面。既有 `/undo` 回滚源码，不替代档案撤销。

### 3.4 前台加载与过程卡片

前台读取是独立开关：`anamnesis.memory_enabled` 管自动背景记忆；`context.project_memory_enabled` 仅额外关闭自动项目档案，不关闭用户档案。同目录直接 `ANAMNESIS.md` 优先，兼容 `.logox/ANAMNESIS.md`，祖先发现止于 Git 根或文件系统根。

必需系统规则和当前回合先保留；自动记忆上限为窗口比例和剩余空间的较小值，默认 5%。整份文档按 cwd → 用户 → 近到远祖先选择；放不下就整份跳过，原因在 `/anamnesis status` 可见，不截断事实，不删除磁盘文档。只在请求边界检查版本，文本与估算缓存不进入逐键输入路径。

一次 `run_id` 在两种 TUI 中都只占一张卡片，绑定启动时项目最近对话的会话。运行中另一会话收到指令，本次卡片不迁移；新运行再选最近会话。暂停任务在原会话续做时复用身份，另一会话启动新运行，旧记录仍可查。会话 JSONL 只保存无模型角色的 `anamnesis_ref`，回放恢复原位置后异步加载预览；缺少引用但有明确归属的运行附在该会话末尾。恢复结束再次核对会话，将读取期间新到事件按序号合并，避免串会话、重复卡片或旧分析丢失。旧窗口已经结束时不继续计时。计时为首次开始后的经过时间，包含同运行暂停期间，并非纯模型计算耗时。

活动卡片头部复用 10Hz 字符动画，表示任务仍在运行，不代表模型已经返回文本；完成 `✓`、失败 `✗`、暂停 `Ⅱ`、中断 `■` 为静态状态，动画与计时停止。完整批次尚有待审资料时，使用 `checkpoint` 事件／`continuing` 阶段，显示“批次已保存／等待续做”、静态 `↻` 和剩余片段数；交接期间停止动画，下一批开始恢复呼吸，不刷暂停通知。旧窗口结束后的 continuing 预览恢复为可续做暂停。当前会话的真实暂停、失败和整体完成另加普通通知，包含状态与原因；有保存与候选时显示“部分采纳”，全候选显示“无可采纳记忆”，附两类数量，不抢焦点、不弹模态框；重复事件及历史恢复不重复通知。计时／动画只更新头部，复用已排版的思考和阶段正文。

点击或 `Ctrl+T` 展开，可看实时思考、阶段问题／依据／取舍／结论／修订、MD 差异、最终发现／下一步建议，以及文件／来源读取明细（开始、完成或错误，完整内容通过 trace 查询）。预览最多 64 条分析、50 条变更、32 项操作、末尾 12000 字思考；长字段节选。完整分析／差异通过 `/anamnesis report [run_id]`，全部原始过程通过 `/anamnesis trace [run_id]`。旧记录没有会话归属时不猜测绑定，只在项目历史入口访问。

快捷键与普通思考共用 `expand_reasoning`；`Ctrl+O` 只控制工具／diff。点击反转当前实际展开状态，`Ctrl+T` 清理普通思考与入梦的单卡片覆盖，`Ctrl+O` 不清理入梦覆盖。新卡片跟随本会话开关，重开默认折叠，已保存正文仍可展开；沿用已有缓存键。

完整事件先追加并 flush，再原子替换 `preview.json`。预览写入失败报告保存异常，但不声称已追加事件丢失；重开首次追加从有效日志尾部恢复序号，半截尾行补换行留作异常证据。预览损坏明确提示，trace／report 仍可查。服务线程校验展示数据，TUI 不依赖入梦实现类型；思考与静态阶段分别缓存，思考增量不重排全部旧阶段。默认主屏滚出物理屏的卡片仍保留终端旧快照，最新逻辑卡片／报告显示最新状态，沿用阅读位置保护。

## 4. 接口、配置与验证

```toml
[anamnesis]
enabled = true
memory_enabled = true
provider = "ollama"             # 也可 lm-studio
model = ""                      # 必须自行填写已安装的本地模型完整名称
idle_seconds = 1800
sleep_start = "00:00"
sleep_end = "08:00"
request_timeout_s = 180          # 连续无模型数据期限；持续生成不受总时长限制
nap_max_steps = 4
sleep_max_steps = 64             # 单批保护；不完整提案暂停，手动／新资料继续
user_archive_tokens = 800
project_archive_tokens = 1600
prompt_memory_max_ratio = 0.05
```

修改 `~/.logox/config.toml` 后重启；现有 `/reload` 只校验配置，不替换运行中的配置。入梦模型独立于 `/model`，不会自动猜测模型名称。端点取相同提供商的配置，只接受 `localhost`、`127.0.0.1`、`::1`，关闭环境代理和重定向。窗口采用静态配置：先查同一提供商的 `model_windows`，未命中用 `context_window`；至少 4096，否则解释并停止。不请求 `/api/ps` 或 `/api/show` 探测窗口；配置值需要与本地服务实际启用窗口一致，不能用原生训练上限代替事实。

| 接口 | 返回／行为 |
|---|---|
| `AnamesisService.start(mode='auto', manual=True)` | 开始独立任务或说明当前为何不能开始 |
| `note_activity(kind)` / `note_foreground_state(busy)` | 同步记录活动，不扫描或写文件 |
| `request_close()` / `aclose()` | 禁止新启动、取消并等待收尾；重复关闭安全 |
| `history(session_id=None)` / `run_record(run_id, trace=False)` | 项目历史／指定会话预览，固定运行报告或完整过程 |
| `latest_report()` / `status()` | 当前项目报告／中立状态 |
| `AnamesisRunner.run(...)` / `validate(...)` | 完整提案／核验后可保存项及拒绝原因 |

## 5. 取舍与待验证问题

选择独立包是为了把后台任务从前台回合中分开，避免共用 messages、统计或工具权限。单用户串行队列牺牲同时整理速度，换取档案一致性和交互优先；保持当前任务直到完成／暂停，避免最近对话持续变化造成抢占。

首版尚未做：自主实验副本、修改与测试、候选代码审批；slash 档案撤销／手工接管界面；真实模型误记评测；静态窗口配置与本地服务实际窗口不一致的检测；源文件全覆盖证明；大日志字节级增量扫描和旧记录清理。改变会话时重新扫描、长运行续做记录增长仍需后续压测。不能把只读发现写成已测试通过的优化收益。

项目时效采用保守界线，较新的无关会话也可能让旧事实进入候选，不宣称准确识别每条事实的过期时间。旧日志缺少时间不从 mtime／文件名猜时间；长眠可读取当前文件补证。时效检查针对拟入档条目，阶段分析与下一步建议仍是待核验研究内容。候选保留在 report／trace，未实现跨运行自动重试候选。

后续优先验证真实本地模型在纠正、临时项目要求、引用场景和历史回滚上的误记率，再优化大日志读取与长报告按需加载。任何写源码或执行测试能力另起设计评审，不扩展现有只读权限。

### 会话时间依据（2026-10-05，已实现并通过离线验收）

入梦来源 SourceRef.timestamp 使用正、有限 Unix 秒或 null；null 是时间未知，兼容旧 0 哨兵／非法值，不能用读取时间补造新证据。采集保持原始记录摘要与来源 ID，资料由日志本身的 timestamp／旧 ts 提供时刻。整理及独立核验请求携带 current_timestamp 与带时区 current_time，便于比较资料年龄。模型须在阶段分析说明时间和时效依据，短期状态／计划可降低旧资料的重要性；稳定明确偏好不因时间自动失效，未知时间不直接推断过期、删除或完成。既有最新非 assistant 项目依据／当前文件核验保护保留，不新增未经确认的衰减公式或自动删除规则。

来源没有可靠时间时，最新时刻计算与会话队列时间排序忽略该项；时间未知项目状态仍留候选，不造成数值比较异常。模型返回新日期的叙述不能让旧证据变新。验收包括模型输入 null／当前时刻、旧数值及 ISO 日期兼容、未知／非有限时间安全、工具结果真实时间可用于当前项目事实、SourceRef 恢复旧 checkpoint 和原日志不被改写。
