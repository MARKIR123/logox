## 阅读与维护约定

先读 08 的装配流程，再读 01 的单轮流程；其余模块按当前问题进入。每篇固定五节：定位与边界、源码地图、机制、接口与验证、取舍与问题。

接口以源码实际签名为准；测试通过只能证明测试覆盖的行为。离线测试不等于真实模型、MCP 服务或终端的在线验收。性能数字应同时注明输入规模、环境和测量方法，不能从局部函数推广成产品整体提速。

功能变动先补对应模块的设计、失败边界和验收条件，再改代码，最后更新状态。跨模块改动同时更新相关文档，明确拥有该行为的模块；决策写入 `../00-decision-log.md`，复盘写入 `../PROJECT-REVIEW.md`，当前接手状态写入 `../ARCHITECTURE.md` 第 11 节。
