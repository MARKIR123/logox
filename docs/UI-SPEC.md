# Logox 界面与视觉规范 (UI-SPEC)

| 项目 | 内容 |
|---|---|
| 文档版本 | v0.1（首版） |
| 状态 | **待用户评审** |
| 依据 | **D37（美观与界面友好为第一优先级）**、D12（全屏多窗格）、D13（折叠卡片）、D14（内联 diff）、D15（键位）、D16（状态项）、D17（主题与布局配置化）、D35（三套主题） |
| 约束力 | **任何 UI 相关模块在编码前，必须先在本文件中找到对应组件规范**（D37 ③）。没有规范就写 UI 代码 = 违规 |

> **本文件的存在理由**：D37 把「美观」定为第一优先级后，视觉决策就不再是「实现完成后再调」的收尾工作，而是所有渲染接口的**输入**。先定形，再编码。

## 1. 设计目标

| # | 目标 | 可检验标准 |
|---|---|---|
| G1 | **一眼看懂正在发生什么** | 任何时刻，状态栏 + 时间线足以回答「在等模型 / 在跑工具 / 在等我授权 / 出错了」 |
| G2 | **长时间阅读不累** | 正文对比度 ≥ 4.5:1；工具输出的次要信息降噪但不消失 |
| G3 | **信息密度可调** | 折叠/展开、面板开关、状态项开关全部可配，而非写死 |
| G4 | **中文与代码同样好看** | CJK 宽度按 2 cell 精确计算；中英混排不错位 |
| G5 | **任何终端都不崩** | 无真彩色、无 Unicode 字形、极窄/极矮终端均有降级路径 |
| G6 | **键盘优先，鼠标可选** | 所有功能都有键位可达；鼠标为增强而非依赖 |

## 2. 布局骨架

### 2.1 标准布局（≥100 列）

```
┌──────────────────────────────────────────────────────────────────────┐
│ timeline (scrollable)                      │ side panel (switchable) │
│                                            │                         │
│  you                                       │  Files                  │
│  ─────────────────────────────────────     │   src/logox/app.py      │
│  refactor the retry logic                  │   src/logox/kernel/...  │
│                                            │                         │
│  logox                                     │  MCP                    │
│  ▸ thinking (2.4s, 340 chars)              │   filesystem    ready   │
│  I'll look at the retry helper first...    │                         │
│                                            │  Memory                 │
│  ✓ read  src/logox/kernel/errors.py  0.1s  │   ~/.logox/LOGOX.md     │
│  ✓ grep  "retry" --glob "*.py"       0.2s  │   ./LOGOX.md            │
│  ✓ edit  src/logox/kernel/retry.py   0.4s  │                         │
│    └ diff +8 -3              Ctrl+O 展开    │                         │
│  ✻ shell  pytest tests/test_retry.py 1.2s  │                         │
│                                            │                         │
├────────────────────────────────────────────┴─────────────────────────┤
│ > _                                                                  │  ← 输入区（1–8 行自适应）
├──────────────────────────────────────────────────────────────────────┤
│ deepseek-chat · ctx 42% · 12.4k tok (cache 87%) · 42 tok/s · #7 · ✻  │  ← 状态栏（**固定最底 1 行**）
└──────────────────────────────────────────────────────────────────────┘
```

> **底部两行（D47）**：`输入区 → 状态栏`。状态栏**永远占据终端最后一行**，对齐 Claude Code
> 与 Pi 的使用习惯；输入区紧贴其上，视线不用在上下之间来回跳。
>
> **提示行已按需求移除**（D47）：键位不再常驻占用一行，改为**输入 `/help` 或按 `F1`**
> 输入 `/help` 弹出帮助浮层查看完整键位表与命令列表。

> 图中的文字刻意用 ASCII 与英文——**这是本规范的一部分**：布局示意图必须能用等宽 ASCII 精确对齐，避免 CJK 宽度歧义。

### 2.2 断点与降级

| 终端尺寸 | 布局 | 降级动作 |
|---|---|---|
| **≥100 列 且 ≥24 行** | 单栏 | 无 |
| **80–99 列** | 单栏 | 状态行按优先级裁剪（§5.1） |
| **<80 列** | 紧凑 | 工具卡片摘要缩短（隐藏参数细节）；diff 进入紧凑模式（见 §5.6）；状态栏只显示优先级最高的 3 项 |
| **高度 <20 行** | 极简 | 时间线可视区至少 6 行；状态栏始终保留 |
| **宽度 <40 列** | 兜底 | 只保留消息正文与最小工具摘要；浮层自动收窄（放不下授权弹窗时**明确拒绝并说明原因**） |

### 2.3 尺寸规则

**垂直堆叠顺序（自上而下）**：`时间线（跟随内容）` → `输入区（1–6 行）` → `状态栏（1 行）`

| 区域 | 规则 |
|---|---|
| **状态栏** | **固定 1 行**，内容超出时按 §5.1 的优先级裁剪 |
| 输入区 | 1 行起，随内容增长，最多可见 6 行；再多时**内部只显示尾部** |
| 时间线 | 渲染全部历史。**不做虚拟化**：超出屏幕的部分交给终端自己的回滚缓冲（D80） |
| 浮层 | 贴在内容末尾之上（像 `fzf`），**不居中**——居中需要把帧补齐到整屏高度，那会往回滚缓冲灌十几行空白 |

> **键位提示**：不再有常驻提示行（D47）。输入框为空时右侧显示一行淡色提示，
> 完整键位表由 `/help` 渲染，内容来自 `src/logox/tui/keymap.py` 的 `KEYMAP`（单一事实来源）。

## 3. 色彩系统

### 3.1 语义化色板（**禁止在组件里直接写颜色名或色值**）

组件只允许引用下列语义 token，具体色值由主题文件提供（§8）。这是三套主题能零成本切换的前提。

| Token | 用途 |
|---|---|
| `bg_base` / `bg_raised` / `bg_overlay` | 主背景 / 卡片与面板背景 / 浮层与弹窗背景 |
| `text_primary` / `text_muted` / `text_faint` | 正文 / 次要信息（耗时、路径）/ 装饰性信息（分隔、占位） |
| `accent` | 焦点、运行中、可交互提示 |
| `success` / `warning` / `danger` / `info` | 成功 / 警告 / 错误 / 中性提示 |
| `border_subtle` / `border_strong` | 弱分隔 / 强边框与聚焦框 |
| `diff_add_fg` / `diff_add_bg` | 新增行前景 / 背景 |
| `diff_del_fg` / `diff_del_bg` | 删除行前景 / 背景 |
| `overlay_scrim` | 浮层背后的压暗层 |

### 3.2 三套内置主题（D35）

| 主题 | 基底色板（D43） | 定位与关键约束 |
|---|---|---|
| **`logox-dark`（默认）** | **Catppuccin Mocha** | 日常主力，深色低刺激；正文对比度 ≥ 4.5:1 |
| **`logox-light`** | **Catppuccin Latte** | 明亮环境 / 投影演示；与 Mocha **同家族**，明暗切换观感一致 |
| **`logox-contrast`** | 自研（以 Mocha 为骨架加深） | 无障碍 / 低质量终端；正文对比度 **≥ 7:1**；**不得仅靠颜色区分状态**（必须辅以符号，见 §10） |

> **为什么选 Catppuccin（D43）**：主流开源配色里只有它自带**成体系的深浅双版本**（Mocha / Latte），语义色一一对应，因此深色与浅色主题的观感天然一致；Tokyo Night 缺官方浅色版、Nord 浅色版对比度偏弱，都不适合作为高对比主题的基础。

### 3.3 对比度要求

| 内容 | 最低对比度 |
|---|---|
| 正文与代码 | 4.5:1 |
| 次要文本（耗时、路径、工具名） | 3:1 |
| 装饰性文本（分隔符、占位） | 不要求，但不得低于 1.5:1 以免完全不可见 |
| 高对比主题的全部文本 | 7:1 |

## 4. 排版与间距

| 项 | 规则 |
|---|---|
| **宽度单位** | 一切宽度按 **cell** 计算；中文/日文/韩文按 **2 cell**。**统一走 `rich.cells.cell_len`，禁止 `len()`**  |
| **间距刻度** | 只有三级：0 / 1 / 2 空格。禁止出现 3 以上或非整数间距 |
| **时间线嵌套** | 每层 2 空格 + `│` 竖线引导；最多 2 层（消息 → 工具卡片 → 卡片内容） |
| **边框** | 使用 Unicode box 字符；终端不支持时降级为 ASCII `+-|`（§9） |
| **代码块** | 与正文左对齐 + 2 空格缩进；不做额外包裹边框（避免视觉噪音） |
| **长文本换行** | 按 cell 宽度硬换行（不用 `textwrap`），代码块不换行而是允许横向滚动标记 `→` |
| **省略** | 统一用 `…`（Unicode 不可用时用 `...`） |

## 5. 组件规范

每个组件必须在本节有完整定义（结构 / 状态 / 尺寸 / 交互）才可编码。

### 5.1 状态栏 `StatusBar`（D16 / D38 / D39 / D42）

**位置**：**固定在终端最后一行**，输入区与提示行在其上方（D38，对齐 Claude Code 与 Pi）。

**结构**：单行，各状态项之间用 ` · ` 分隔。左端＝模型与上下文，右端＝运行中状态与告警标记。

**默认开启（D42，共 4 项）**：`model`（含思考档位）、`context`、`throughput`、`cache`
**默认关闭**：`tool`、`turn`、`usage`、`timing`、`permission`、`git`、`session`

| 裁剪优先级（数字越大越先被裁掉） | 状态项 key | 显示格式 | 默认 |
|---|---|---|---|
| 13（最先裁） | `session` | `sess 7f3a` | ⬜ 关 |
| 12 | `git` | `main*` | ⬜ 关 |
| 11 | `permission` | `ask · 1 pending` | ⬜ 关 |
| 10 | `timing` | `Σ 12:34 · llm 8:12 · tool 3:40` | ⬜ 关 |
| 9 | `usage` | `12.4k tok · $0.0031` | ⬜ 关 |
| 8 | `turn` | `#7` | ⬜ 关 |
| 7 | `tool` | `✻ shell 1.2s` | ⬜ 关 |
| 6 | `cache` | `cache 87%` | ✅ 开 |
| 5 | `throughput` | `42 tok/s` | ✅ 开 |
| 4 | `context` | `ctx 42%` | ✅ 开 |
| 3 | `model` | `deepseek-v4-pro · high` | ✅ 开 |
| 2 | **右端运行提示** | `esc to interrupt` / `queue 2` | 运行中恒定（**永不裁剪**） |
| 1（最后裁） | 告警标记 | `?` / `⚠` / `✗` 前缀 | 恒定 |

#### 5.1.1 `model` 项的格式：`<模型名> · <思考档位>`（D42）

```
deepseek-v4-pro · high        ← 有思考过程
deepseek-chat                 ← 无思考过程 → 不显示档位后缀
claude-sonnet-4-5 · medium
```

**规则：没有思考过程就只显示模型名，不显示档位。** 与主流 agent 工具（如 Claude Code 的 `Opus 4.1 · high`）保持一致。

| 档位 | 含义 | 映射到厂商参数（**适配器职责，不得外泄到内核**） |
|---|---|---|
| `off` | 显式关闭思考 | Anthropic：不传 `thinking`；OpenAI 兼容：`reasoning_effort="minimal"` |
| `low` / `medium` / `high` | 思考预算档位 | OpenAI 兼容：`reasoning_effort`；Anthropic：`thinking.budget_tokens` 按档位取值 |
| `auto`（**默认**） | 交由模型自身决定 | 不传档位参数 |

| 边界 | 处理 |
|---|---|
| 模型不支持思考 | 忽略档位、**只显示模型名**；在 `/debug` 面板记一条 warning，**不在主界面打扰** |
| 档位由谁设置 | `provider.thinking_effort` 配置项，或运行时 `/effort <off\|low\|medium\|high\|auto>`（切换后写入 `state.toml`） |
| 档位切换后 | 时间线插入一行 `text_faint` 提示：`—— 思考档位：medium → high ——` |
| 各厂商字段名 | 三家完全不同（`reasoning_effort` / `thinking.budget_tokens` / DeepSeek 推理模型默认开启），**必须由 Provider 适配器统一映射** |

#### 5.1.2 右端运行提示（D39 / D41 / R4）

| 情形 | 显示 |
|---|---|
| 模型生成中 或 工具执行中 | `esc to interrupt`（`accent`）——**用户永远知道有中断出口**（US-10 的可发现性） |
| 队列非空（无论是否在生成） | `queue 2`（`text_muted`），紧邻运行提示 |
| 等待授权 | **左端**出现 `accent` 色 `?`，避免没注意到弹窗 |

#### 5.1.3 其余项的口径与配色

| 状态项 | 计算口径 | 边界 |
|---|---|---|
| `throughput` | **输出 token ÷ 本次模型请求耗时**（只算生成阶段，不含排队与首字等待） | 无数据时显示 `—`，不显示 `0 tok/s` |
| `cache` | `usage.cached_input_tokens ÷ usage.input_tokens`，取整百分比 | Provider **未上报**缓存字段时**整项不显示**（不伪装成 `0%`） |
| `turn` | 已完成回合数 + 1，格式 `#N` | 会话起始即 `#1` |
| `timing` | `Σ` 会话总用时 · `llm` 模型请求累计 · `tool` 工具执行累计 | 默认整体关闭；三字段可独立关闭 |

| 情形 | 配色 |
|---|---|
| 上下文占用率 ≥75% / ≥90% | `context` 转 `warning` / `danger` |
| 缓存命中率 <30%（且已上报） | `cache` 转 `warning`——通常意味着上下文前缀频繁变动或刚压缩过 |
| 出错 / 重试中 | 右端显示 `danger` 色简短类别 + `RetryScheduled` 倒计时 |
| `timing` 开启时 | `llm` 与 `tool` 中占比 >80% 的一方**加粗** |

**宽度不足时的合并规则**：若用户同时开启了 `usage` 与 `cache`，先合并为 `12.4k tok (cache 87%)`；仍不足则按上表优先级从高编号开始裁剪。**右端运行提示与告警标记永不被裁**（它们是"现在在干什么"的唯一线索）。

**交互**：`/status` 看会话事实；`/permissions` 等面板**尚未实现**（§5.10）。

**数据来源（架构约束）**：状态栏**不直接读取内核状态**（`ARCHITECTURE.md` 规则 R3 红线）。它由 `tui/metrics.py` 这一事件订阅者把事件流归约为 `SessionMetrics`：`SessionStart` → 起始时间；`ModelRequestFinished` → usage / duration / cost；`ToolCallFinished` → duration；`TurnFinished` → 轮次递增。**因此内核无需为状态栏新增任何代码**——这正是 D7 事件总线设计的直接回报。

### 5.2 用户消息 `UserBlock`

| 项 | 规则 |
|---|---|
| 标记 | 左边距 1 空格 + `accent` 色竖线 `│` |
| 标题 | `you`（`text_faint`，小写，不带冒号） |
| 正文 | `text_primary`，左缩进 2 空格，按 cell 宽度换行 |
| 附加上下文 | 若输入含 `@file` 引用，正文下方以 `text_faint` 列出被引用的文件路径 |

### 5.3 助手消息 `AssistantBlock`

| 项 | 规则 |
|---|---|
| 标记 | `◆`（`accent`）+ `logox` 标题 |
| 正文 | 行内 Markdown 渲染；代码块走 Rich Syntax 高亮 |
| 流式呈现 | 增量按 `ui.stream_fps` 合并后落成块——**必须在回合结束前就上屏**（否则就是"一次性蹦出来"） |
| 空回复 | 不渲染空块，改为在时间线插入一行 `text_faint` 的「（无文本输出）」 |

#### 5.3.1 Markdown 表格（D115）

| 项 | 规则 |
|---|---|
| 识别 | GFM 表格：`\| 表头 \|` 行**紧跟**一行 `\|---\|` 分隔行；分隔行列数必须与表头一致（不一致就按普通段落渲染，避免"正文里一个竖线"被误吞） |
| 形态 | 闭合框线表（`┌─┬─┐` / `├─┼─┤` / `└─┴─┘`），框线着 `md_table_border` |
| 表头 | `md_heading` + **粗体**，下方一条 `├─┼─┤` 分隔线 |
| 列宽 | 按内容自适应；整表放不下时，按"各列**超出**最小宽度的部分"成比例收缩（每列保底 4 cell，始终 `sum(列宽) + 框线 ≤ 宽度`） |
| 单元格超宽 | **按列折行，绝不截断**（与 §5.21"话说到一半没了"是同一类故障） |
| 对齐 | 分隔行的 `:--` 左 / `:-:` 中 / `--:` 右，表头与正文一体生效 |
| 极窄终端 | 连一列都放不下时**降级为记录式列表**（`• 表头：内容`，续行悬挂对齐），不画框线——框线在 20 列里只会把内容挤成碎片 |
| 单元格内联 | 支持行内 Markdown（粗体 / 斜体 / 行内代码 / 链接）；**不支持**跨行合并（`<br>`、`colspan`），按字面量渲染 |

### 5.4 推理块 `ReasoningBlock`（D31）

| 状态 | 表现 |
|---|---|
| 生成中（收起） | `▸ 思考中… (1.2s)` — `text_muted`，`▸` 缓慢脉动 |
| 已完成（收起，默认） | `▸ 思考 (2.4s · 340 字)` + 右侧 `Ctrl+T 展开` |
| 展开 | 正文用 `text_muted` + 斜体，左侧 `border_subtle` 竖线，最大高度 20 行后内部滚动 |
| 隐藏（`ui.show_reasoning = "hidden"`） | 完全不渲染 |

**约束**：推理内容**不计入上下文预算**（D31）；换模型时历史推理自动剔除。推理块的展开状态**不持久化**（下次默认收起，避免视觉噪音累积）。

> **展开键是 `Ctrl+T`（D125）**：思考链与工具卡/ diff 是**两个独立职责**的开关 ——
> 用户经常只想核对"执行了什么"（`Ctrl+O`），而不想收下冗长的内心独白。
> 旧版一个键管两件事时，用户被迫同时收下不想要的那一半。

### 5.5 工具卡片 `ToolCard`（D13）

**折叠态 = 一行摘要**（这是长会话可读性的关键）：

| 状态 | 格式 | 颜色 |
|---|---|---|
| 排队中 | `· edit  src/config.py` | `text_faint` |
| 运行中 | `✻ edit  src/config.py  ⟳ 1.2s` | `accent` |
| 成功 | `✓ edit  src/config.py  0.4s` | `success`（耗时用 `text_faint`） |
| 失败 | `✗ shell  npm test  exit 1  3.1s` | `danger` |
| 被拒绝 | `⊘ shell  rm -rf build  (denied)` | `warning` |
| 被中断 | `◼ shell  npm run dev  (cancelled)` | `warning` |

**摘要字段来源**：由工具自己声明（`ToolSpec.summary_template`），**不是 UI 猜的**。每个工具必须定义：显示什么参数、成功时附加什么统计、失败时显示什么。

#### 编辑类卡片默认不展开（D40）

`edit` / `write` 成功后的卡片**保持折叠**。
> ⚠️ **订正（D132 / user 裁定）**：原先折叠态是**两行**（摘要行 + 下面一行 `└ diff +N -M` 徽标，
> 外加 `Ctrl+O 展开` 提示）。用户原话：
> "虽然没完全展开，但 diff 和工具调用还是有一块在" —— 要求**完全折叠**：
> **一行只显示「操作（工具名）+ 参数 + 状态色（= 执行结果）」**。
> 变更徽标与键位提示因此都**只在展开态出现**。旧写法（保留作对照）：

```
✓ edit  src/logox/kernel/retry.py  0.4s
  └ diff +8 -3                     Ctrl+O 展开
```

| 情形 | 徽标 |
|---|---|
| 修改既有文件 | `diff +8 -3` |
| 新建文件 | `diff +42 -0  (new)` |
| 整文件重写 | `diff +120 -118  (rewrite)` |
| 二进制文件 | `binary changed  1.2 KB → 1.4 KB` |
| 大 diff（>200 行） | `diff +312 -48  (large)` |

- **默认折叠 = 整块不渲染**（D132）：折叠时不输出任何行（包括路径与徽标行）——
  变更统计已由工具卡那一行承担，再留一行就是用户明确否掉的"折叠了却还占一块"。
  `Ctrl+O` 展开为完整 `DiffView`（§5.6），并在**展开态**写出 `Ctrl+O 折叠` 让人知道怎么收回。
  > ⚠️ **两条历史订正**：
  > ① （D125/CHANGE-006）本条原写「`Ctrl+E` 一次展开全部」——**那个键不存在**（`Ctrl+E` 是输入框的"跳到行尾"，见 §7.2），且与 `Ctrl+O` 语义重复，已删；
  > ② （D125-b）折叠时原先**一个字提示都不给**，于是补了 `Ctrl+O 展开`；
  > ③ （D132）再往后一步：折叠态的那些字整体撤掉（见上），提示改挂在**展开态**—— 用户实测的反馈是"我无法关闭 diff、没有这个快捷键"，根因正是**展开后不给收回的路**。
- **失败仍然自动展开**（D13）：编辑匹配失败、写入失败时卡片自动展开并显示错误与「文件中最相近的片段」——此时用户必须看到原因；
- **徽标配色**：`+N` 用 `success`、`-M` 用 `danger`，符号与颜色同时表意（§10）；
- **展开状态不持久化**：跨会话回到折叠（与推理块一致，避免视觉噪音累积）。

**展开态**内容顺序（**实现状态**见每行末尾，D139 核对）：
1. 完整参数（JSON 美化，2 空格缩进）✅ *D139 实现*（`Block.args_text` + `fmt.format_args`）
2. 结果主体（调用该工具的 `DisplayHint` 渲染器，默认 `diff` → §5.6，其余 → 纯文本/表格）
   ✅ *D139 实现*：`diff` 走 `render_diff`（`ToolCallFinished.display` → `attach_diff`）；
   `text` 走纯文本；`lines`/`table`/`error` **暂无专用渲染器，仍走纯文本**（不假装支持）
3. 尾部元信息（`text_faint`）：耗时、退出码、输出行数、是否被截断 ⚠️ *未实现*（只有耗时，在卡片行上）

**交互**（**已按 D125 订正为实际实现**）：
- `Ctrl+O` 展开/折叠**全部工具卡与 diff**（**全局**，不是"当前聚焦卡片"）；
- `Ctrl+T` 展开/折叠**全部思考链**（**全局**，与 `Ctrl+O` 互不影响）；
- ⚠️ **本条原先写的是**「`Ctrl+O` 展开/折叠**当前聚焦**卡片；`Tab` 在卡片间移动焦点；`Ctrl+E` 展开/折叠**全部**」——
  **这三件都没实现**：没有"焦点卡片"概念、`Tab` 没有跨卡片移动的绑定、`Ctrl+E` 已被输入框占用。
  已按现状改为**全局**口径（用户裁定 Q2=A）。若将来要做"聚焦单卡"，那是**另一件事**
  （需要焦点概念 + 焦点键 + 焦点视觉标记），不要以为改个开关就行。
- **编辑/写入卡片默认折叠**，仅显示 `diff +N -M` 徽标（D40）；
- 失败卡片**默认自动展开**（D13）；⚠️ 副作用：该卡此后**收不起来**（块级 `expanded=True` 优先于全局开关），已登记为 CHANGE-006 F-40；
- 展开状态：**会话内保持，跨会话不持久化**。

### 5.8b 提示框（浮层）统一规范（D170）

**所有**用圆角框的提示框（`/` 补全、`/model`、`/theme`、`/resume`、`/rewind`、权限弹窗、`/help` 面板）共用同一套口径：

| 项 | 约定 | 为什么 |
|---|---|---|
| 宽度 | **整宽**（= 当帧可用宽度） | 同一屏里两种宽度看着像没对齐；窄终端由 `frame_box` 按 cell 精算兜底 |
| 边框颜色 | **四边同色，且用输入框的专属 token `input_border`** | 用户裁定「提示框的颜色用和输入框一样的颜色」；同一屏里两套边框色看着不协调。⚠️ 页脚曾漏改用更暗的 `border_subtle`，改完头/身又漏改回过一次 |
| 选中行 | **`bold accent` 前景强调**（整行含左右竖线）＋ `❯` 标记，**不用底色** | 用户裁定「我喜欢这个高亮色的设计，提示框统一这样设计」；无底色是 D81 的硬约束。实现上**逐行应用、样式不含换行符** ⇒ 机制上不可能溢出到下一行 |
| 位置 | 贴在**内容末尾之上**（`fzf` 式），不居中 | 居中要把帧补齐到整屏高度，会往回滚缓冲灌空行（§2.3）|
| 键位提示 | 写在**下框线**里的页脚（如 `Tab 补全 · ↑↓ 选择 · Esc 关闭`） | 页脚只列**真的可用**的键 —— 写一个按了没反应的键比少写一个糟糕得多 |

> ⚠️ **例外**：`/` 补全**不是浮层**（它插在「时间线」与「输入框」之间，见 §5.9）——本条其余约定（宽度 / 边框颜色 / 选中标记 / 页脚）对它同样适用。

### 5.9 输入区 `PromptInput`（D15）
### 5.9 输入区 `Editor`

| 项 | 规则 |
|---|---|
| 高度 | 最多 6 行可见；更多时**内部只显示尾部**（正在编辑的那一段永远看得见） |
| 提示符 | **无**（D126：用户裁定去掉 `❯` —— 圆角边框本身已经说明"这里是输入框"）。`Editor(prompt=...)` 参数保留，装配处传一个字符串即可换回 |
| 换行 | **`Ctrl+Enter` / `Ctrl+J` / `Shift+Enter`**（D130 恢复了 `Shift+Enter`；`Alt+Enter` 仍是去掉的）。口径：`Enter`(`CR`) = 提交；**单独一个 `LF`（`\n`）= 换行**（与参考实现 Pi 逐字节一致）—— 而 `LF` 正是 **Windows Terminal 上 `Ctrl+Enter`**、以及**所有终端上 `Ctrl+J`** 发出来的东西（本机探针实测），所以它**不依赖任何终端协议**。另认 `CSI 13;…u`（Kitty）与 `CSI 27;…;13~`（xterm `modifyOtherKeys`）作为带修饰位的备选来源。⚠️ **`Shift+Enter` 与 `Alt+Enter` 已于 D129 去掉**（按下去不换行、也不提交）；且在分不出修饰位的终端上 `Shift+Enter` 仍等于 `Enter`（物理上限）。⚠️ 代价：若某终端把 **Enter 键**发成 `LF`，那种终端上要用 `Ctrl+M` 发送 |

> **为什么 Windows Terminal 上 `Shift+Enter` 做不到？** 参考实现 Pi 的**官方文档**给出了同样结论：`pi-tui/README.md` 写"`Shift+Enter`, `Ctrl+Enter`, or `Alt+Enter` — New line (**terminal-dependent**, Alt+Enter most reliable)"，`pi-coding-agent/README.md` 更直接："Multi-line | Shift+Enter (**or Ctrl+Enter on Windows Terminal**)" —— 即 **Pi 在 Windows Terminal 上同样用 Shift+Enter 换不了行**，它只是把 `Ctrl+Enter` 写成了 WT 用户的标准答案。
| 光标 | **终端自己的硬件光标**——编辑器只发一个零宽标记告诉渲染器"光标在哪"（D82）。好处：原生闪烁、中文输入法候选窗自动跟随 |
| 空输入时 | 右侧显示一行淡色键位提示（`Enter 发送 · /help 键位 · …`），开始打字即消失 |
| 粘贴 | **一次粘贴 = 一次插入**，绝不逐条回车（§5.11 的"绝不静默丢弃/拆分输入"） |
| 历史 | `↑`/`↓` 在**空输入**时浏览历史输入 |

> **双轨标记可开关（D176）**：用户消息的 `▌` 与模型输出的 `▎ ` 是**纯装饰** —— 终端里「占了格子的字形一定会被复制」，所以按 `Ctrl+B` 可以让它们**整个消失**（复制得到纯文本），默认显示。
>
> **已实现（D169）**：**`/` 命令补全** —— 行首敲 `/` 即在输入框上方列出候选，
> 随输入按前缀过滤，`Tab` 补全（带尾随空格）、`Enter` 先补全再提交、`↑↓` 移动、`Esc` 只关列表。
> 候选包含**未实现的命令**（灰显 + "（未实现）"标注），以便用户分清"没做"与"打错"。
> 该提示框**不是浮层**（D162-b）：它作为**布局的一行插在「时间线」与「输入框」之间**，外观复用既有圆角提示框 ⇒ **输入框永远完整可见、永不被遮挡**；
> 帧在中间长高时，时间线尾部滚进终端回滚缓冲，**输入框位置不动**。
>
> **裁定不做（D173）**：`@` 文件补全与**参数值补全** —— 用户裁定「这不是核心功能」。
> 参考实现 Pi 同样**没有**参数值补全（需要选值的命令一律开弹窗）；`@` 提及则会直接增加上下文成本。
> **仍未实现**：生成中入队（§5.11）。帮助里也不会为它们列键位——**写着一个按了没反应的键，比少写一个糟糕得多**。

### 5.10 侧栏面板 —— **已删除（D85）**

原先设计的是 32 列常驻侧栏，放 Files / MCP / Memory / Permissions / Debug 五个面板。
**它在实现之后被删掉了**，原因有两条：

1. **用户明确不要**："不要常驻侧栏……我要的就是一个没有冗余文件、干净清爽的界面"；
2. **它占的宽度是正文的**：终端宽度是稀缺资源，而侧栏内容是"偶尔看一眼"的信息
   ——为偶尔一眼常驻牺牲 32 列正文不划算。

**替代方案**：这些信息改为**按需浮层**（`/status`、`/debug` 已经这么做）。
`/files`、`/mcp`、`/memory`、`/permissions` 的浮层版本**还没实现**，
因此它们在 `/help` 里被明确标为"还没实现"，而不是假装可用。

> **代价（诚实登记）**：侧栏能"一眼看到"，浮层要按一下键。
> 如果将来发现某些信息需要常驻，正确的做法是把它压进**状态行**（一行、按优先级裁剪），
> 而不是把侧栏请回来。

### 5.11 指令队列 —— **计划中（M5+），尚未实现**

设计意图（保留供将来实现）：**生成中**按 `Enter` 时，当前输入**不发送也不丢弃，而是入队**，
前一条回合自然结束后自动发送队首。

| 项 | 规则 |
|---|---|
| 触发 | 生成中在输入区按 `Enter` |
| 位置 | 输入区上方；队列非空时自动出现 |
| 等待模式 | FIFO：前一回合结束后自动发送队首 |
| 上限 | 默认 20 条；超出时**拒绝入队并明确提示**，不静默丢弃 |
| 命令入口 | `/queue` 查看 · `/queue send` · `/queue clear` |

今天的实现是"生成中按 Enter 照样开一个新回合"，由内核的并发闸门管住。

## 6. 动效与反馈

| 项 | 规则 | 理由 |
|---|---|---|
| 流式渲染节流 | 默认 **10 fps** 合并刷新（`ui.stream_fps` 可配 5–30） | 高 token 速率下不刷屏、不卡顿 |
| 差分重画 | **只重画变化的那几行**；内容没变时**一个字节都不写** | 不闪、不浪费（实测：空闲帧 0 字节） |
| 工具运行指示 | `✻` 常驻 + 耗时数字 | 让"卡住"与"在跑"可区分 |
| 状态变化延迟 | 用户操作到界面反馈 **<100ms** 可见 | 感知即响应 |
| 整屏重绘 | 只在**宽度/高度变化**或"要改的行已滚出可视区"时发生 | 那两种情况下增量重画没有意义 |
| 动画 | 仅允许流式光标；**禁止**淡入淡出、滑动等过渡 | 终端场景下动画是噪音 |

## 7. 键盘与焦点模型

### 7.1 焦点规则

| 规则 | 说明 |
|---|---|
| 默认焦点 | 始终是**输入区** |
| `Esc` 语义（分层） | ① 有浮层 → 关闭它（选择器里有筛选时先清筛选）；② 无浮层且**生成中** → 中断生成；③ 无浮层且空闲 → 无副作用（留给将来"清空草稿"） |
| 浮层打开时 | 焦点整个交给浮层；关掉之后**一定交还输入区**（漏了这一步的症状是"浮层关了但打字没反应"） |
| 鼠标 | **不接管**（D78/D85）。选择、复制、滚轮全部由终端提供，和 `bash` 里一样 |

| `Shift+Enter` | 换行（**需终端支持**修饰位；Windows Terminal 上它与 `Enter` 同字节，见 §5.9 / D130） |
| **`\` + `Enter`**（行尾反斜杠） | 换行（**不依赖终端**的退路**；D131 照参考实现 Pi 搬来）：光标前一字符是 `\` 时，`Enter` 吃掉它并换行而不是提交。⚠️ 代价：**只有「以反斜杠结尾的消息」**需要多一步（打两个反斜杠再回车，或打完按 `←` 再回车）；反斜杠在开头/中间（如 `\Pi`、`C:\Windows`）**完全不受影响** |
| `←` `→` `↑` `↓` `Home` `End` | 在输入框里移动光标；空输入时 `↑`/`↓` 翻历史 |
| `Ctrl+W` / `Alt+退格` | 删掉前一个词 |
| `Ctrl+U` / `Ctrl+K` | 删到行首 / 行尾 |
| `Ctrl+A` / `Ctrl+E` | 跳到行首 / 行尾 |
| 粘贴 | 一次粘贴 = 一次插入（不会逐条发出去） |
| `Ctrl+O` | 展开/折叠**工具卡与 diff**（全局） |
| `Ctrl+T` | 展开/折叠**思考链**（全局，与 `Ctrl+O` 互不影响） |
| `Esc` | 见 §7.1 的分层语义（关浮层 → 中断生成） |
| `Ctrl+C` | **生成中**：中断（不退出）；**空闲**：第一下只提示、**2 秒内第二下**才退出（D69——终端里 `Ctrl+C` 常被当复制键，一下就走等于每次复制都丢会话） |
| `Ctrl+D` | 退出 |

> `Alt+Enter` **已从键位表里去掉**（D129）：按下去**不换行、也不提交**（显式吞掉），
> 因此不在 `/help` 里列出。`Shift+Enter` 按用户裁定于 D130 **恢复**。
| 滚轮 / `Shift+PgUp` | 往上翻——用**终端自己**的回滚缓冲 |
| 拖选 + 终端复制键 | **由终端提供**（D78：Logox 不启用鼠标追踪）。它们不是 Logox 的键位，而是终端的 |
| 浮层里：`↑` `↓` | 在选项之间移动 |
| 浮层里：`1` … `9` | 数字直达（选第几项） |
| 浮层里：直接打字 / `Backspace` | 筛选（选择器）/ 删一个字符 |
| 浮层里：`Enter` / `Esc` | 确认 / 取消（**权限弹窗里 `Esc` = 拒绝**） |
| 浮层里：`PgUp` / `PgDn` | 滚动长内容（帮助、参数、事件流） |

### 8.2 规则

| 规则 | 说明 |
|---|---|
| 缺失 token | **拒绝加载**并明确列出缺失项（不做静默兜底，避免"部分正确"的诡异配色） |
| 色值格式 | 仅接受 `#RRGGBB`；不接受颜色名（保证降级时可精确换算到 256/16 色） |
| 版本 | `schema_version` 不匹配 → 拒绝加载并提示；不自动迁移 |
| 用户主题 | 放在 `~/.logox/themes/*.toml`，与内置同名时**用户优先** |
| 加载失败 | 回退到 `logox-dark` 并在状态栏显示 `warning` 提示，**不阻断启动**（P-5） |

## 9. 终端能力探测与降级

启动时探测并写入 `SessionStart` 事件（在启动摘要块中公示）：

| 能力 | 探测方式 | 降级后果 |
|---|---|---|
| 真彩色 | `COLORTERM` 含 `truecolor`/`24bit`，或 `TERM` 含 `direct` | `Console.color_system` 为 256 → 主题色自动量化到 256 色；16 色 → 量化到 16 色并简化 diff 背景 |
| Unicode 字形 | 检测 `WT_SESSION` / `TERM` / 配置项 `ui.icon_set` | `ascii` 集：`+ x ! > # -` 等；边框降级为 `+-|` |
| 鼠标 | `TERM` 不含 `dumb` 且未被禁用 | 关闭鼠标交互，全部功能仍可由键盘完成 |
| 备用屏幕 | **不使用**（D80/D85） | 内容写进终端**主屏**，于是滚动、选中、复制全部由终端提供——这正是重写要换来的东西 |
| 终端尺寸 | `shutil.get_terminal_size()` | 按 §2.2 断点降级 |

> **`nerd` 图标集**：默认**关闭**（需用户显式开启），因为 Nerd Font 未安装时会出现豆腐块。开启后 `Files` 面板等位置使用文件类型图标。

## 10. 可访问性

| 项 | 要求 |
|---|---|
| **不靠颜色单独表意** | 每个状态必须同时有**符号**（§5.5 的 `✓ ✗ ✻ ⊘ ◼`）与颜色；高对比主题下尤其严格 |
| 对比度 | 见 §3.3 |
| 动画可关 | `ui.animations = false`（§6） |
| 屏幕阅读器友好 | 关键状态变化同时写入 `Notification` 事件，不依赖视觉（后续可接钩子做语音播报） |
| 键盘可达 | 所有交互均有键位；鼠标仅为增强（§7） |
| 不做仅靠 emoji 的表意 | emoji 字形缺失率高，一律用 Unicode 几何符号 + ASCII 兜底 |
