# 本地模型请求误经代理的排查

事件日期：2026-10-07。整理日期：2026-10-09。适用范围：OpenAI 兼容提供商的回环地址请求。原诊断中的服务名称、私人路径和会话内容已去除；历史观察不是今日服务状态。

## 现象与定位

本地模型接口在直接请求时返回 HTTP 200，而继承环境代理时出现 HTTP 502。服务本身能响应，因此只检查模型进程或改变提示词无法解释差异。

将相同请求的客户端环境分开测试，再使用可控代理确认 SDK 请求路径，证据指向客户端默认继承代理环境。关键是最终 base URL 是否为回环地址，而不是提供商的展示名称。

## 当前处理与代价

回环地址使用不继承代理环境的 SDK HTTP 客户端；远端请求保留原有代理行为。这样避免本地请求绕到代理，但不能据此保证所有“本地模型”地址都受同一策略：局域网地址和其他部署需要核对实际 URL。

客户端在构造时缓存，修改运行环境后应重新构造或重启，不能只改变环境变量便认定现有对象已更新。Anamnesis 另有更严格的直连地址与重定向限制，见 [提供商](../../modules/04_providers.md) 和 [入梦](../../modules/09_anamnesis.md)。

## 验证边界

历史诊断包含直接/代理对照与 SDK 客户端试验。本次文档整理没有重新启动该服务。后续使用 tests/contract 的 OpenAI 本地客户端测试，并在目标环境做真实直连检查。

这类问题的排查方法是保持请求内容相同，只改变网络路径，避免同时修改服务、模型与客户端导致原因不清。
