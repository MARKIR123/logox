## 问题

## 已确认选择与代价

| 选择 | 主要替代方案 | 理由与接受的代价 |
|---|---|---|
| TUI 开启时运行，只读审阅；不自动实验或修改源码 | 关闭后独立服务、在实验副本修改与测试 | 减少生命周期和安全复杂度；后台只能提出研究结论，不能把建议声称为实际验证 |
| 合并小憩与长眠，不按昼夜分两套流程，不设整次总时长上限 | 白天短任务、夜间长任务及总时长限制 | 保持同一套研究状态；需要无响应超时、重复检测和明确进度避免无限空转 |
| 仅开放项目参与，同项目所有窗口空闲且前台结束后才能自动入梦 | 只看单窗口空闲、扫描关闭项目 | 避免同项目仍在交互时后台整理；一个活跃窗口会推迟整个项目 |
| 全局串行，按项目最后提交指令时间排序，并给已服务项目让出轮次 | 每窗口或每项目独立并行 | 简化本地模型占用与记忆写入竞争；多个项目需要等待 |
| 卡片固定归属启动时该项目最新提交会话 | 每会话重复展示、运行时跟随新会话搬家 | resume 能追溯原过程；其他窗口需要历史入口查阅 |
| 已提交消息与 /anamnesis stop 唤醒当前窗口；仅编辑草稿不暂停 | 任意按键立即暂停、全局唤醒所有项目 | 不因查看或编辑打断研究；提交时再让前台优先 |
| 用户与项目 ANAMNESIS.md 分层，档案有预算，以修订替代无限追加 | 无界追加、统一混合档案 | 背景保持精简、项目信息隔离；必须筛选，未采纳内容留作候选 |
| 依据驱动提案、宿主结构检查、独立模型语义核验后按条采纳 | 模型自称成功便提交、整批全收或全弃 | 阻止无来源和不完整输出直接入档；独立请求仍是同一模型，不能保证绝对正确 |

当前持久化、工具边界和重复自检机制以 [模块说明](../../modules/09_anamnesis.md) 为准。此表保留取舍，不复制接口或全部配置。
