# 用户级人设的存放位置与生效方式

日期：2026-10-09。状态：已由用户裁定并已实现（工作树未提交）。适用 `codex/anamnesis` 当前工作树。

## 问题

Logox 的人格基底原先散在两处不一致的地方：`app.py` / `cli.py` 里硬编码的一段基础提示，以及一份**写了却没人读**的 `~/.logox/LOGOX.md`（6642 字节）。同时 `tools/sync_system_prompt.py` 声称维护"仓库母本 `docs/SYSTEM-PROMPT.md` → 用户级文件"的同步链，而该母本当时并不存在（`--check` 退出码 2），脚本本身也未被 git 跟踪。结果是三段说法互相矛盾，用户改这份文件毫无反应。

## 已确认选择与代价

| 选择 | 主要替代方案 | 理由与接受的代价 |
|---|---|---|
| 接通用户级文件：存在即作为系统提示第一段 | 删除机制、只登记问题不修 | 用户明确选择接通；代价是同一仓库在不同机器上人设不同，系统提示前缀因此变化会让厂商侧 KV 缓存那一段按全价重算一次 |
| 人设源就是 `~/.logox/LOGOX.md` 本身，不设仓库母本 | 仓库保留 `docs/SYSTEM-PROMPT.md` 母本 + 同步脚本 | 用户裁定以用户级文件为唯一事实来源；代价是它不受 Git 管理，换机器需自行放一份，仓库不能自洽复现人设 |
| 内置基础提示保留为回落层（运行环境、工具清单与工具规范） | 文件存在时把内置提示整段替换 | 保证文件缺失时 Logox 仍有人格与运行约束；代价是文件存在时出现两个身份句（措辞重复，尚未消除） |
| 读不进来时**整份跳过**并说明原因，不截断、不部分注入 | 截断到上限、静默忽略 | 人设被砍一半会得到自相矛盾的规则；代价是超大文件等于没有人设，用户需主动查看 `/reload` 报告 |
| 人设不受 `[context].project_memory_enabled` 影响 | 复用同一个开关 | 该开关语义是"项目规范"，与人设是两件事；代价是多一个概念，删除或改名文件才是人设的开关 |

`tools/sync_system_prompt.py` 的前提（仓库母本）已不成立，但它未被 Git 跟踪，删除会丢文件，因此**保留原状**，去留另行确认。

## 验证与改变成本

验收证据：`tests/unit/test_persona.py` 17 项（含幂等重读、来源列表、两条装配路径与 `/reload` 报告），并已做三次断开接线的先红后绿检查。真实模型读人设后的行为差异没有离线证据。

改变成本：换存放位置或恢复仓库母本需要改 `build_runtime`/`_context_params` 的传参并更新本文件；消除"两个身份句"只需在 `app._system_prompt` 里把身份句与运行块拆开，属局部改动。
